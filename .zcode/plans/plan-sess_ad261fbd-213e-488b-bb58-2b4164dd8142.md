## 合併計畫:PCA9685 FF 掃描註冊 + SPI 空值容忍(一次實施)

### A. PCA9685 部分(`slave/driver/pca9685_drv.py`)

**1. FF(0xFF)自動掃描註冊**
- 常數:`_PCA_ALL_CALL = 0x70`(ALLCALL 廣播位址)、`_PCA_AUTO_SCAN = 0xFF`。
- config `address` 清單中遇到 `"0xFF"`:
  - `i2c.scan()` 掃描匯流排,排除 `0x70`(廣播位址,不當一般裝置 — 舊專案 bug 根因)。
  - 對每個掃到位址做 probe:讀 MODE1 暫存器(`readfrom_mem(addr, 0x00, 1)`)成功才視為 PCA9685 並註冊。
  - 每個註冊成 `PixelController("i2c_pixel", {pixel_IO, Q:16, order:"W", dStay})`,與現行一致。
  - log 印出掃到/排除/註冊的位址清單。
- 抽出共用小函式建立 PixelController,避免 FF 分支重複程式碼。
- 其他位址(含 `"0x70"`)維持現行行為:`"0x70"` 直接 `PCA9685(i2c, address=0x70)`,因 PCA9685 ALLCALL 預設啟用,每幀 `show()` 寫 0x70 = **對全部板子同時廣播**(不需額外程式碼,支援你要的「對 0x70 操作 = 廣播」)。

**2. `slave/lib/hw/pca9685.py`** — 檔案頂部加註解:address=0x70 時所有 writeto_mem 皆 ALLCALL 廣播(寫一次全部板子同時收到);0x70 不應作為一般裝置註冊。

**3. `ports/P4/ESP32-P4-ETH/config.json`**
- `PCA9685.list[0].address` 從 `["0x40"]` → `["0xFF"]`(自動掃描註冊全部,排除 0x70;你現在只接 0x40 就只註冊它,日後加板不用改 config)。
- 順帶修正 `uartMotor` 兩筆 `GPIO.uart` 從 `1` → `0`(目前 UART 只有 1 條在 index 0,`1` 是越界,保持 index 語意避免日後啟用即錯)。

### B. SPI 部分(`slave/driver/spi_drv.py`,config 不用改)

**1. 空 list 視同 null(容忍跨語言空值寫法)**
- `init_spi` 中:`data = item.get("data_pins")`;若 `data` 非 None 但 `len(data)==0` → 設為 None。
- 之後既有邏輯自動走 `d = (mosi,)`(你的 mosi=7 → 1-line SPI 成功)。
- 效果:`[]`、`null`、缺省三種寫法全部等效,你現有 `"data_pins": []` 不用動。

**2. fallback 防 boot 崩潰**
- lcd_bus except 區塊內 `_make_machine_spi(...)` 包 try/except:失敗 log error 並回 None。
- `init_spi` 迴圈:item 建失敗(spi None)就 warn + `continue`,不再整個 init 失敗。

### C. 驗證
- `python -B -m py_compile slave/driver/pca9685_drv.py slave/driver/spi_drv.py slave/lib/hw/pca9685.py`
- `python3 -B -m json.tool ports/P4/ESP32-P4-ETH/config.json`
- 清 `__pycache__`

### 不做的事
- 不動 `tft_drv.py` 的 `spi_id`(硬體 id 語意,S3 依賴)。
- 不動 `slave/config.json`(非你目前用機)。
- 不處理 APA102/SPI 的 host 衝突殘留(屬開機順序/電源問題,重刷/重插電即可;若仍發生再單獨看)。
